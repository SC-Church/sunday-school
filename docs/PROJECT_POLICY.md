# 송촌장로교회 주일학교 관리 시스템 정책 문서 v1.0

배포 운영 기준에서 반드시 지켜야 할 정책을 정의한다.  
본 문서는 `PRD`(기능 요구)와 `AI_SESSION_SCRIPT`(개발 협업 규칙)를 보완하는 운영 기준 문서다.

## 1. 운영 원칙
- 본 서비스는 주일학교 운영 지원을 위한 내부 관리 서비스다.
- 프로젝트의 최우선 제약은 `무료/저비용 운영`이다.
- 데이터 정확성(출석, 달란트, 권한)이 UI 편의보다 우선한다.
- 변경 사항은 기능 추가보다 안정성 저하 방지를 우선 검토한다.

## 2. 역할 및 권한 정책
- 로그인 사용자만 실데이터에 접근 가능하다.
- 게스트 경로(`/guest` 이하)는 로그인 없이 공개하되, 데모 데이터만 노출한다. 실제 학생·교사 정보, 외부 링크(회의록·재정 관리 등), 쓰기 기능은 게스트 화면에 포함하지 않는다.
- 승인 상태가 `APPROVED`인 교사만 핵심 기능 접근 가능하다.
- `ADMIN`만 가입 관리/권한 관리/관리자 전용 기능 접근 가능하다.
- 권한 검증은 클라이언트가 아니라 서버에서 최종 판정한다.

## 3. 인증 정책 (이메일/비밀번호)
- 인증 방식은 자체 회원가입 + 이메일/비밀번호 로그인이다(2026-09 Google OAuth에서 전환).
- 가입한 계정은 승인 대기 상태로 시작하며, 관리자가 승인해야 서비스를 이용할 수 있다.
- 가입 시 이메일 소유 확인을 하지 않으므로, 이메일만으로 관리자 권한을 주지 않는다. 첫 관리자는 `yarn sheets:make-admin <이메일>`로 지정한다.
- 비밀번호는 scrypt 해시로만 저장하며, 평문·임시 비밀번호를 기록하지 않는다. 비밀번호 규칙: 영문+숫자 포함 8~64자.
- 로그인 5회 실패 시 10분간 잠근다. 비밀번호 분실 시 관리자가 임시 비밀번호를 발급하고, 교사가 로그인 후 직접 변경한다.
- 기본 토큰 유지 기간은 `30일`로 설정한다.
- `AUTH_SECRET` 등 인증 관련 환경변수는 저장소에 커밋하지 않는다. `AUTH_SECRET`을 바꾸면 모든 교사가 다시 로그인해야 한다.

## 4. 데이터/시간 정책
- 날짜와 시간은 `항상 한국시간(Asia/Seoul)` 기준으로 계산/표시한다.
- 출생일/출석일 저장 시 타임존 오차가 없도록 `+09:00` 기준을 사용한다.
- 학년 계산, 주차 계산, 대시보드 일정 기준일은 공통 유틸/공통 서비스 로직을 사용한다.
- 동일 의미 계산 로직(학년, 나이, 주차)은 중복 구현하지 않는다.

## 5. 출석 및 달란트 정책
- 출석 기준일은 일요일 단위로 관리한다.
- 출석 토글/달란트 조정은 동시 작업을 고려해 서버에서 경쟁 상태를 방어한다.
- 출석 연동 달란트와 수동 조정 달란트는 구분해 기록한다.
- 모든 변경 작업은 성공/실패를 사용자에게 즉시 알린다(토스트 정책 적용).

## 6. UI/접근성 정책
- 시맨틱 태그 사용을 기본 원칙으로 한다.
- 키보드 접근 가능 요소(`button`, `a`)를 우선 사용한다.
- 상태 전달은 색상만 사용하지 않고 텍스트를 함께 제공한다.
- 공통 버튼 체계(`btn-*`)와 전역 컬러 변수(`--color-*`)를 재사용한다.

## 7. 성능/비용 정책
- 서버 렌더 중심 구조를 기본으로 한다.
- 상호작용이 많은 화면은 클라이언트 컴포넌트 + React Query를 사용한다.
- Link prefetch는 기본 `false`로 유지해 불필요한 서버 요청을 줄인다.
- 외부 API 호출은 캐시/재검증 주기를 명시해 비용과 안정성을 함께 관리한다.

## 8. 인코딩/품질 정책
- 모든 텍스트 파일은 UTF-8을 사용한다.
- 한글 깨짐 징후가 있으면 즉시 복구 후 린트/타입체크를 재실행한다.
- 배포 전 최소 검증 절차:
1. `yarn eslint .`
2. `yarn tsc --noEmit`
3. `yarn build`

## 9. 배포/환경변수 정책
- 배포는 Vercel을 기준으로 한다.
- 운영 환경변수는 Vercel Project Environment Variables에서 관리한다.
- 민감정보(`AUTH_SECRET`, `APPS_SCRIPT_TOKEN`, API Key)는 GitHub에 저장하지 않는다.
- 데이터 저장소는 Google Sheets 스프레드시트 1개다(2026-09 Neon Postgres에서 전환). 시트 컬럼(스키마) 변경이 포함된 배포는 `src/server/db/sheet-schema.ts`와 실제 시트 1행 헤더가 일치하는지 반드시 확인한다(`yarn sheets:init`이 새 탭·새 컬럼을 붙여 준다).
- 조회는 20초 인스턴스 캐시를 거친다. 시트를 직접 고치면 최대 20초 뒤 반영되며, 앱을 쓰지 않는 시간에 고친다.
- 학년 진급은 매년 2월 말 관리자가 [학년 진급]에서 실행한다. 실행 전 새 학년도 반 구조와 매핑을 확인하고, 실행 후 되돌리려면 조직 관리에서 개별로 옮긴다.
- 스프레드시트는 Google Drive에 두고 Apps Script 웹 앱(`apps-script/Code.gs`)으로만 앱과 연동한다(Google Cloud 콘솔 미사용). 시트 자체는 공유하지 않거나 관리 교사에게만 공유하고, 링크 공개("링크가 있는 모든 사용자")는 쓰지 않는다. 학생 개인정보가 들어 있다.
- 웹 앱 URL은 누구나 호출할 수 있으므로 `APPS_SCRIPT_TOKEN`(= 스크립트 속성 `API_TOKEN`)이 유일한 보호 수단이다. 유출이 의심되면 두 값을 함께 새 값으로 바꾼다.

## 10. 장애 대응 정책
- 로그인 장애 시 우선 확인:
1. `AUTH_SECRET`/`NEXTAUTH_URL` 설정과 쿠키/도메인 불일치 여부
2. 로그인 잠금(5회 실패, 10분) 여부 — 관리자가 비밀번호를 초기화하면 풀린다
3. 시트 `teachers.passwordHash` 값 존재 여부(비어 있으면 관리자 초기화 필요)
- 데이터/권한 이상 시 우선 확인:
1. 서버 권한 검증 경로
2. 시트 1행 헤더와 `sheet-schema.ts` 컬럼 일치 여부(불일치 시 오류 메시지에 탭/행/컬럼이 표시됨)
3. Apps Script 웹 앱 배포 상태(액세스 권한 "모든 사용자", 최신 버전 배포 여부)와 토큰 일치 여부

## 11. 변경 관리 정책
- 정책 변경은 문서 먼저 수정하고 코드에 반영한다.
- 운영에 영향이 큰 변경(인증, 권한, 날짜 계산, 출석/달란트 로직)은 PR/커밋 메시지에 변경 이유를 명시한다.
- 기능 완료 후 사용자 공지용 변경 요약(무엇이 바뀌었는지)을 남긴다.
