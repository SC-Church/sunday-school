# 주일학교 관리 시스템 업그레이드 계획 (2026-09)

요청받은 10개 요구사항의 구현 가능성 검토 결과와 실제 구현 설계를 정리한 문서다.
저장소는 Google 스프레드시트(Apps Script 웹 앱 경유)를 그대로 쓰고, 그 위에 **부서 → 반 → 학생** 구조와
학년도(3월 시작) 단위 반 배정 이력을 추가한다.

## 1. 요구사항별 구현 가능성

| # | 요구사항 | 판정 | 구현 방식 |
|---|---|---|---|
| 1 | 교회 이름 생성 | 가능 | `settings` 탭(`church_name`) — 관리자 [조직 관리]에서 수정. 헤더·로그인 화면에 표시 |
| 2 | 청년부·청소년부·유년부 등 부서명 생성 | 가능 | `departments` 탭. 관리자가 추가·이름 변경·순서·비활성 처리 |
| 3 | 부서별 반과 학생 기본정보를 CSV로 생성 | 가능 | `classes` 탭 + 관리자 [학생 일괄 등록] 화면. 한글 헤더 CSV 업로드 → 서버 검증(미리보기) → 일괄 저장. 없는 부서·반은 자동 생성 옵션 |
| 4 | 주일마다 반별 교사가 반별 출석 체크 | 가능 | 출석 관리 화면을 **반 단위**로 재구성. 교사에게 배정된 반이 기본 선택되고, 출석 토글은 기존 낙관적 업데이트 유지 |
| 5 | 반별 교사가 한 해 출석현황(통계)을 쉽게 조회 | 가능 | 새 화면 [출석 통계] — 학년도·반 선택 → 주차 × 학생 출석표, 학생별 출석 횟수·출석률, 주차별 출석 인원 차트 |
| 6 | 학년·부서 변경 시 해당 부서로 정보 전송 | 가능 | `enrollments`(반 배정 이력) 탭. 반 이동 = 기존 배정 종료 + 새 배정 생성. 학생 레코드·출석·달란트는 `studentId`로 이어지므로 정보가 그대로 따라간다 |
| 7 | 학년이 바뀌면 한 학년 위로 이전 정보와 함께 이동 | 가능 | 관리자 [학년 진급] 마법사 — 이전 학년도 반 → 새 학년도 반 매핑(이름의 숫자 +1 자동 제안, 부서 마지막 반은 다음 부서 첫 반 제안) 확인 후 일괄 실행 |
| 8 | 개인별·반별 출석현황 | 가능 | 개인별: 기존 학생별 출석부 모달(학년도 기준) 유지. 반별: 5번 화면 |
| 9 | 관리자 모드에서 매년 반 현황·반별 학생 현황 수정 | 가능 | 관리자 [조직 관리] — 학년도 선택 → 부서/반 CRUD, 반별 교사 배정, 반별 명단에서 학생 이동·미배정 처리 |
| 10 | 새친구 추가 및 출석 횟수 확인 | 가능 | 학생에 `isNewFriend`, `firstVisitDate` 추가. 출석 화면의 [새친구] 패널에서 빠른 등록 + 누적 출석 횟수 표시, 정착 처리 버튼 |

### 이번에 바꾸지 않는 것
- 달란트(포인트) 기능, 대시보드의 생일·주간 일정 카드, 게스트 데모 화면의 성격(실데이터 미조회)
- 인증 방식(이메일/비밀번호 + 관리자 승인)
- 생년월일 기반 학년 라벨(`src/utils/grade.ts`)은 **참고 정보**로 유지한다. 실제 소속은 반 배정이 결정한다.

## 2. 데이터 모델 변경 (스프레드시트 탭)

새 탭 4개, 기존 탭 컬럼 추가 2개. 기존 데이터는 그대로 두고 `yarn sheets:init`이 헤더만 늘린다.

| 탭 | 컬럼 | 비고 |
|---|---|---|
| `settings` (신규) | key, value, updatedAt | `church_name` |
| `departments` (신규) | id, name, sortOrder, isActive, createdAt, updatedAt | |
| `classes` (신규) | id, departmentId, schoolYear, name, sortOrder, teacherIds, isActive, createdAt, updatedAt | 반은 **학년도별**로 존재. `teacherIds`는 쉼표 구분 |
| `enrollments` (신규) | id, studentId, classId, schoolYear, status, reason, startedAt, endedAt, note, createdAt, updatedAt | status `ACTIVE`/`ENDED`, reason `MANUAL`/`IMPORT`/`TRANSFER`/`PROMOTION`. 학생은 학년도당 ACTIVE 배정 최대 1개 |
| `students` (컬럼 추가) | … + note, isNewFriend, firstVisitDate | 특이사항·새친구 |
| `attendances` (컬럼 추가) | … + classId | 출석 당시 소속 반(통계용, 과거 행은 비어 있음) |

학년도(`schoolYear`)는 3월 시작 기준으로 `getSchoolYearInKst()` 한 곳에서 계산한다. 2026년 3월~2027년 2월 = `2026`.

## 3. 화면·API 변경

### 메뉴
- 공통: 대시보드 · 출석 관리 · **출석 통계(신규)** · 학생 관리 · 교사 정보 · (외부 링크들) · 레크레이션
- 관리자: 가입 관리 · **조직 관리(신규, 부서/반/명단/교회 이름)** · **학년 진급(신규)**
- 학생 관리 안의 **[CSV 일괄 등록]** 버튼(관리자)

### 화면
| 경로 | 내용 |
|---|---|
| `/attendance?class_id=` | 반 선택 칩(부서별 그룹, 내 반 우선) · 출석 토글 · 달란트 조정 · [새친구] 패널(빠른 등록, 출석 횟수) · 달란트 기록 |
| `/attendance/stats?school_year=&class_id=` | 반/전체 선택 · 요약(재적, 평균 출석률) · 주차별 출석 인원 차트 · 주차 × 학생 출석표 · 학생별 출석 횟수/률 |
| `/students?class_id=` | 반 선택 칩 · 반/새친구/특이사항 표시 · 등록/수정 폼에 반·특이사항·새친구 필드 추가 |
| `/students/import` (관리자) | CSV 템플릿 다운로드 · 업로드 · 미리보기(행별 오류) · 일괄 등록 |
| `/admin/organization?school_year=` (관리자) | 교회 이름 · 부서 관리 · 학년도별 반 관리(교사 배정) · 반별 명단(학생 이동) |
| `/admin/promotion` (관리자) | 이전 학년도 → 새 학년도 반 구조 복사 · 반 매핑 확인 · 진급 실행 |
| `/teachers` | 담당 학년 대신 **담당 반** 표시(교사 수정 폼의 학년 선택 제거) |

### API (모두 승인 세션 필요, `/api/admin/*`는 관리자만)
- `GET/POST /api/attendance/interactive?class_id=` — 반 단위 조회/출석 토글/달란트
- `POST /api/students` · `PATCH /api/students/[id]` — 반·특이사항·새친구 필드 추가
- `POST /api/students/new-friend` — 새친구 빠른 등록 / `POST /api/students/[id]/settle` — 정착 처리
- `POST /api/students/import` (`dry_run` 지원), `GET /api/students/import/template`
- `POST /api/admin/settings` · `/api/admin/departments` · `/api/admin/classes` · `/api/admin/enrollments` · `/api/admin/promotion`

## 4. 반응 속도 개선

실측: Apps Script 읽기 1회 = **2.4~4.9초**(2026-09-27, 5개 탭). 지금은 페이지마다 읽기 1회 이상이라 화면 전환마다 이만큼 걸린다.

1. **서버 데이터셋 캐시** (`src/server/db/dataset.ts`) — 전체 탭을 한 번에 읽어 인스턴스 메모리에 20초 캐시. 조회 페이지는 캐시만 읽으므로 대부분의 화면 전환이 즉시 응답한다.
2. **쓰기 후 자동 갱신** — 쓰기 트랜잭션은 항상 새로 읽고(동시 저장 충돌 검사 유지), 저장이 끝나면 캐시를 비운 뒤 `after()`로 응답 후 백그라운드에서 다시 읽어 둔다. 사용자가 다음 화면으로 넘어갈 때 이미 캐시가 준비돼 있다.
3. **한 번 읽기** — 페이지 하나가 탭을 여러 번 나눠 읽던 것을 전체 1회 읽기로 통일(읽기 호출 수 자체를 줄임).
4. **즉시 반응 UI** — 출석 토글·달란트는 기존 낙관적 업데이트 유지, 새친구 등록·학생 이동도 API 응답 전에 화면 먼저 반영. 느린 첫 로딩에는 `loading.tsx` 스켈레톤을 둬 화면이 멈춘 것처럼 보이지 않게 한다.
5. **한계** — 쓰기 1회(2~3초)는 Apps Script 특성상 줄일 수 없다. 근본 해결은 `docs/db_upgrade.md`의 저장소 교체.

## 5. 작업 순서

1. 데이터 모델·유틸(학년도 주차, CSV 파서, 진급 매핑, 통계 계산) + 단위 테스트
2. 저장소 계층(`repository.ts`) — 캐시 도입, 부서/반/배정/설정 함수
3. 출석 서비스·API 반 단위로 재구성, 학생 API 확장, 관리자 API
4. 화면: 출석 관리 → 출석 통계 → 학생 관리/폼/CSV → 조직 관리 → 학년 진급 → 교사/메뉴/헤더
5. 게스트 데모 데이터 갱신(반 정보 추가), 문서(CLAUDE.md, README, PRD) 갱신
6. 검증: lint · prettier · tsc · vitest · next build · 가짜 Apps Script 서버로 전체 시나리오(e2e) · 실제 시트에 `yarn sheets:init`

## 6. 운영 시 알아둘 점
- **매년 2월 말**: [학년 진급]에서 새 학년도 반 구조 복사 → 매핑 확인 → 실행. 3월 1일부터 앱이 새 학년도를 자동으로 기준으로 삼는다.
- CSV 일괄 등록은 관리자만. 같은 이름+생년월일 학생은 중복으로 잡아 건너뛰거나 오류로 표시한다.
- 과거(컬럼 추가 전) 출석 행은 `classId`가 비어 있어 반별 통계에서는 "당시 배정 반"을 학년도 배정 이력으로 되짚어 계산한다.
